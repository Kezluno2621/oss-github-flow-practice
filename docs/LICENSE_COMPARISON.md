
# OSS 라이선스 비교 분석 및 선택 기준

## 1. 개요

본 문서는 OSS 기반 SW 프로그래밍 6주차 실습의 일환으로 주요 오픈소스 라이선스의 특징을 비교하고, 프로젝트에 적합한 라이선스를 선택한 근거를 정리합니다.

비교 대상은 다음과 같습니다.

- MIT License
- Apache License 2.0
- GNU General Public License v3.0 (GPL 3.0)

## 3. 라이선스별 특징

### 3.1 MIT License

MIT는 간단한 조건으로 소프트웨어의 사용, 수정 및 배포를 허용하는 라이선스입니다.

장점:
- 라이선스 내용이 간결함
- 상업적 이용 및 재배포 가능
- 외부 개발자의 재사용이 쉬움
- 작은 프로젝트에 적용하기 편리함

고려 사항:
- 저작권 및 라이선스 고지 유지 필요
- 수정된 소스코드 공개를 강제하지 않음
- 명시적인 특허 허락 조항이 없음

### 3.2 Apache License 2.0

Apache 2.0은 허용형 라이선스로, 특허와 관련된 조건이 명확하게 규정되어 있습니다.

장점:
- 상업적 이용 및 수정 허용
- 기여자의 명시적인 특허 허락 조항 제공
- 기업 및 조직의 프로젝트에 활용 가능

고려 사항:
- 저작권 및 라이선스 고지 유지 필요
- 수정한 파일에 변경 사실 표시 필요
- MIT보다 라이선스 조항이 상세함

### 3.3 GPL 3.0

GPL 3.0은 강한 Copyleft 라이선스입니다.

장점:
- 소프트웨어의 자유로운 사용과 수정 보장
- 배포되는 파생 저작물의 소스 공개 및 라이선스 유지 요구
- 오픈소스 생태계에서 수정 결과를 공유하도록 유도

고려 사항:
- 배포 시 소스코드 제공 등 의무 발생 가능
- 파생 저작물의 라이선스 선택에 제약
- 다른 라이선스와 결합할 때 호환성 검토 필요

## 4. 라이선스 선택 기준

프로젝트의 라이선스를 선택할 때 다음 기준을 고려합니다.

1. 프로젝트 규모와 목적
2. 상업적 이용 허용 여부
3. 수정 및 재배포 조건
4. 소스코드 공개 의무
5. 특허 관련 조항
6. 외부 라이브러리와의 라이선스 호환성

## 5. 프로젝트 라이선스 선택

### 선택한 라이선스: MIT License

OSS GitHub Flow Practice 프로젝트에는 MIT License를 적용하였습니다.

### 선택 이유

첫째, 프로젝트 규모가 작고 교육 및 실습 목적에 적합합니다.

둘째, 다른 개발자가 코드를 자유롭게 사용하고 수정할 수 있습니다.

셋째, 라이선스 조건이 간단하여 오픈소스 협업과 라이선스 관리 방법을 학습하기 좋습니다.

넷째, 외부 의존성이 적은 Python 계산기 프로젝트의 특성과 잘 맞습니다.

### 고려한 대안

Apache 2.0은 명시적인 특허 허락이 필요한 프로젝트에 적합할 수 있습니다.

GPL 3.0은 배포되는 파생 저작물에도 동일한 오픈소스 라이선스를 적용하려는 목적에 적합합니다.

현재 프로젝트는 폭넓은 재사용과 간단한 관리에 우선순위를 두어 MIT를 선택하였습니다.

## 6. 결론

MIT, Apache 2.0, GPL 3.0은 모두 오픈소스 라이선스이지만, 특허 관련 조항과 소스코드 공개 의무 등에서 차이가 있습니다.

본 프로젝트에서는 단순성과 재사용 편의성을 고려하여 MIT License를 적용하였습니다.
