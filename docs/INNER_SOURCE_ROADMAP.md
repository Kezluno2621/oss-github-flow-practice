
# Inner Source 도입 로드맵

## 1. 개요

본 문서는 OSS 기반 SW 프로그래밍 6주차 선택 과제의 일환으로 조직 내부에 Inner Source 개발 방식을 도입하기 위한 단계별 계획을 정리합니다.

Inner Source는 조직 내부에서 오픈소스 개발 원칙과 협업 방식을 적용하여 코드 공유, 재사용 및 협업을 활성화하는 개발 방식입니다.

본 로드맵은 가상의 조직을 대상으로 작성한 도입 계획이며, 실제 운영을 수행한 결과는 아닙니다.

## 2. 도입 배경

조직 내 여러 개발팀이 독립적으로 개발하면 다음과 같은 문제가 발생할 수 있습니다.

- 팀별 중복 코드 작성
- 공통 기능의 재사용 부족
- 팀 간 기술 정보 공유의 어려움
- 코드 리뷰 및 개발 규칙의 차이
- 유지보수 비용 증가

이러한 문제를 개선하기 위해 Inner Source 도입을 제안합니다.

## 3. 도입 목표

1. 조직 내부 코드 공유 및 재사용 활성화
2. 부서 간 개발 협업 확대
3. GitHub 기반 코드 리뷰 문화 정착
4. 공통 개발 규칙 및 문서화 체계 구축
5. 중복 개발 감소 및 유지보수성 향상

## 4. 단계별 도입 로드맵

### 1단계: 준비 및 현황 분석 (1~2주)

주요 활동:
- 조직의 개발 및 협업 환경 조사
- 중복 개발 및 코드 공유 현황 파악
- Inner Source 도입 대상 프로젝트 선정
- 프로젝트 관리 담당자 지정
- 내부 저장소 접근 권한 정책 수립

산출물:
- 현황 분석 보고서
- 시범 프로젝트 목록
- 역할 및 책임 정의서

### 2단계: 협업 환경 구축 (3~4주)

주요 활동:
- 조직 내부 GitHub 저장소 구성
- README 및 CONTRIBUTING 문서 작성
- CODE_OF_CONDUCT 행동 강령 정리
- Feature 브랜치 전략 도입
- Conventional Commits 규칙 적용
- PR 템플릿 및 코드 리뷰 기준 마련

산출물:
- Inner Source 시범 저장소
- 협업 가이드 문서
- 코드 리뷰 체크리스트

### 3단계: 시범 프로젝트 운영 (5~6주)

주요 활동:
- 공통 유틸리티 프로젝트를 대상으로 시범 운영
- Issue를 통한 기능 개선 요청 관리
- Pull Request를 통한 코드 기여
- [MUST] 및 [SHOULD] 태그를 활용한 코드 리뷰
- Wiki를 활용한 개발 문서 관리
- Discussions를 통한 비동기 기술 토론

산출물:
- 시범 프로젝트 PR 및 Issue 기록
- 코드 리뷰 결과
- 협업 개선 의견

### 4단계: 평가 및 개선 (7~8주)

주요 활동:
- 프로젝트 참여 현황 분석
- PR 리뷰 및 Merge 소요 시간 측정
- 공통 코드 재사용 사례 조사
- 개발자 피드백 수집
- 협업 과정의 문제점 분석 및 개선

산출물:
- 시범 운영 평가 보고서
- 개선 과제 목록
- 다음 단계 운영 계획

### 5단계: 조직 전체 확산 (9~12주)

주요 활동:
- 시범 운영 결과 공유
- 다른 개발팀으로 Inner Source 확대
- 공통 저장소 및 문서 템플릿 배포
- 신규 참여자 교육 및 온보딩 지원
- 지속적인 운영 및 개선 체계 마련

산출물:
- 조직 차원의 Inner Source 운영 가이드
- 공통 협업 템플릿
- 교육 및 확산 계획

## 5. 역할 및 책임

| 역할 | 주요 책임 |
|---|---|
| 프로젝트 관리자 | 도입 계획 수립 및 운영 |
| Maintainer | 코드 품질 관리 및 PR 검토 |
| Contributor | 기능 개발 및 코드 기여 |
| Reviewer | 코드 리뷰 및 개선 의견 제시 |
| 문서 담당자 | README, Wiki, 가이드 유지관리 |

## 6. 협업 운영 규칙

- 새로운 기능은 Feature 브랜치에서 개발합니다.
- 변경 사항은 Pull Request를 통해 공유합니다.
- 커밋 메시지에는 Conventional Commits를 적용합니다.
- 코드 리뷰에는 [MUST]와 [SHOULD] 태그를 활용합니다.
- 중요한 기술 결정은 ADR로 기록합니다.
- 비동기 기술 논의는 GitHub Discussions를 활용합니다.
- 조직 내부의 접근 권한과 보안 정책을 준수합니다.

## 7. 성과 측정 지표 (KPI)

| 지표 | 측정 방법 | 시범 목표 |
|---|---|---|
| 참여 팀 수 | 기여에 참여한 팀 집계 | 3개 팀 이상 |
| PR 리뷰 비율 | 리뷰된 PR / 전체 PR | 80% 이상 |
| 평균 첫 리뷰 시간 | PR 생성부터 첫 리뷰까지 | 24시간 이내 |
| 코드 재사용 사례 | 다른 팀의 공통 코드 활용 사례 | 3건 이상 |
| 문서화 비율 | 필수 문서를 갖춘 시범 저장소 비율 | 100% |

위 수치는 실제 측정 결과가 아닌 시범 운영을 위한 목표값입니다.

## 8. 예상 문제 및 대응 방안

### 참여 부족
- 참여자를 위한 온보딩 문서 제공
- 작은 기능 개선부터 기여하도록 유도

### 코드 리뷰 지연
- Maintainer 및 Reviewer 역할 명확화
- 리뷰 응답 목표 설정

### 코드 품질 차이
- 공통 코드 스타일과 테스트 기준 도입
- PR 템플릿 및 리뷰 가이드 활용

### 접근 권한 및 보안 문제
- 조직 내부 저장소 접근 권한 관리
- 민감한 정보가 포함되지 않도록 검토
- 코드 공유 범위와 보안 정책 사전 정의

## 9. 기대 효과

- 조직 내부 개발 생산성 향상
- 중복 개발 감소
- 공통 코드 재사용 확대
- 팀 간 기술 지식 공유
- 투명한 협업 문화 형성
- 유지보수 효율성 향상

## 10. 결론

Inner Source를 효과적으로 도입하기 위해서는 개발 도구뿐 아니라 협업 규칙, 문서화, 역할 분담 및 참여 문화가 함께 마련되어야 합니다.

본 로드맵은 준비, 환경 구축, 시범 운영, 평가, 조직 확산의 5단계로 구성하였습니다.

단계별 실행 결과를 평가하고 개선하면서 조직 전반으로 Inner Source 문화를 확산하는 것을 목표로 합니다.
